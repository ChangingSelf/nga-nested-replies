# NGA 楼中楼脚本 v2.2.0 - 快速使用指南

## 📦 安装方式

### 方式1：使用打包后的文件（推荐）

1. 确保已安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展
2. 打开文件：`nga-nested-replies.user.js`
3. Tampermonkey会自动识别并提示安装
4. 点击"安装"按钮完成

### 方式2：使用原始文件

直接使用 `main.js` 文件（完整的单文件版本）

## 🎯 主要功能

### 1. 渐进式加载
- 默认加载5页后立即展示楼中楼结构
- 后台继续加载更多页面（可配置预加载页数）
- 避免长时间等待

### 2. 智能缓存
- 自动缓存已加载的帖子
- 下次访问直接从缓存读取
- 可配置缓存有效期（1小时-永久）
- 自动容量管理（默认50MB）

### 3. 可折叠进度条
- 位置：右下角
- 加载中：自动展开显示详细信息
- 加载完成：自动折叠为小图标
- 鼠标悬停：展开查看详情

### 4. 配置面板
- 点击右下角⚙️图标打开
- 可配置项：
  - 初始加载页数（1-50页）
  - 预加载页数（0-100页）
  - 页面读取间隔（500-5000毫秒）
  - 缓存有效期（1小时-永久）
  - 最大缓存容量（10MB-200MB）

### 5. 缓存管理
- 查看所有缓存的帖子
- 显示帖子标题、大小、最后访问时间
- 单个删除或全部清空
- 容量使用情况可视化

## 🛠️ 开发者指南

### 目录结构

```
nga-nested-replies/
├── src/                       # 模块化源代码
│   ├── utils/                 # 工具函数
│   │   └── helpers.js         # 格式化、防抖、节流等
│   ├── storage/               # 存储模块
│   │   ├── config.js          # 配置管理
│   │   └── cache.js           # 缓存管理
│   └── ui/                    # UI组件
│       └── progress.js        # 进度条
├── main.js                    # 主文件（包含未模块化部分）
├── build.js                   # 打包脚本
├── package.json               # npm配置
└── nga-nested-replies.user.js # 打包输出（用于安装）
```

### 修改源码后重新打包

```bash
# 安装依赖（仅首次）
npm install

# 打包脚本
npm run build

# 监听模式（规划中）
npm run watch
```

### 打包输出

- 输出文件：`nga-nested-replies.user.js`
- 包含所有模块和主文件内容
- 可直接在Tampermonkey中安装

## 🐛 常见问题

### Q1: 为什么有时候缓存不加载？

**A**: 检查以下几点：
1. 查看浏览器控制台，查找 `[初始化]` 开头的日志
2. 确认缓存未过期（在配置面板查看缓存列表）
3. 尝试清除缓存后重新加载

### Q2: 预加载不工作怎么办？

**A**: v2.1.0已修复此问题。如果仍有问题：
1. 确认使用的是最新版本
2. 检查控制台是否有 `[预加载]` 日志
3. 尝试调整预加载页数配置

### Q3: 进度条挡住内容怎么办？

**A**: v2.1.0已将进度条移到右下角，并且加载完成后会自动折叠。如果还是觉得碍眼，可以等待3秒后自动淡出。

### Q4: 打包后文件变大了？

**A**: 这是正常的，因为添加了详细的JSDoc注释和模块分隔符。实际可执行代码量是减少的。

### Q5: 可以不打包直接使用吗？

**A**: 可以，直接使用 `main.js` 文件，它仍然是完整可用的单文件版本。

### Q6: 如何清除所有缓存？

**A**: 
1. 点击右下角⚙️图标打开配置面板
2. 切换到"缓存管理"标签
3. 点击"清空所有缓存"按钮

### Q7: IndexedDB什么时候实现？

**A**: 当前GM_setValue性能已经足够，IndexedDB迁移建议延后实施。只有在遇到明确的性能瓶颈或容量限制时才考虑迁移。
